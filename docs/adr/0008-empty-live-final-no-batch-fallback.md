# live 空文本不回退批量：audio.cpp ASR 单实例串行锁的实测约束与回退触发条件修正

## Status

accepted

amends: ADR-0005 的回退语义。不推翻「live 为主路径、批量为失败兜底」的核心决策；
修正其两个被实测否定的部分：(a)「回退前 live 连接已关闭，批量请求不会撞上模型
占用」只对**当句**会话成立，跨语句并发下批量会被别的 live 会话无限挂起；(b) 实现
把「协议成功但文本为空」也当作失败触发批量回退，超出并违背了 ADR-0005 的失败
语义。ADR-0005 保留为历史记录。

## Context

排查「闭环无反应」（2026-11-03）时在 audio.cpp@8080（`nemotron-3.5-asr-streaming`，
backend=cuda）实测到：

- **单实例串行锁**：live 请求存续期间服务端持有 ASR 模型占用锁（ADR-0005 已知）；
  但**批量**路由对同一模型同样排队等锁且不返回 busy——同一段 9 s 音频，空闲时
  批量 0.62 s/200；一条 live 会话挂起期间打批量，25 s 内无任何响应（curl 超时）；
  live finish 后立即重打，1.15 s/200。即批量不是「撞上 busy」而是**无限挂起**。
- **空文本是模型的正常输出**：0.35 s 短音频，live 协议成功（done 事件）但
  final=`''`；对同一段音频打批量，同样 0.09 s 返回 `''`。同一模型对同一段音频，
  批量不可能比 live 多识别出内容。

生产表现为二者的乘法：新 Silero VAD（ADR-0007）切出的短碎片（实测 350–480 ms）
live 返回空 → 旧实现按失败回退批量 → 采集泵已为下一句开新 live → 批量挂 15 s
（httpx 总超时）→ 单消费者识别 worker 每句卡 15 s → 端点队列（4）溢出，实测一次
连续说话内 53 次 `endpoint queue full; dropping utterance`，几乎全部语音未达核心。

## Decision

1. **空文本不回退**：`live.finish()` 协议成功但文本为空 → 直接按空丢弃该句
   （DEBUG 日志），不再走批量。批量回退仅保留给 ADR-0005 定义的失败：连接断、
   SSE `error`、`VOICE_IN_ASR_LIVE_TIMEOUT_MS` 超时、服务端拒绝流式。
2. **批量 HTTP 超时 15 s → 8 s**：真失败回退时仍可能撞上他句 live 的模型锁
   （服务端只排队不拒绝，无法在客户端根除）；短超时让识别 worker 快速失败恢复，
   避免拖垮端点队列。正常批量 <1.5 s（RTF 0.14），8 s 余量充分。

## Consequences

- 「说半句/含糊短句没反应」回归为**模型侧正常行为**（短音频识别不出内容），
  不再是 15 s 停摆 + 队列雪崩的系统性失聪；端点队列在连续说话下不再溢出。
- 撞锁的瞬时批量兜底会以 8 s 超时报 `batch asr request failed: ReadTimeout`
  （WARNING）后丢句，属兜底路径的显式降级，不再是隐性雪崩。
- 若未来 audio.cpp 提供多实例/并发 ASR，可重估回退触发条件与超时；本约束是
  服务端部署属性，模块侧只做适配。
